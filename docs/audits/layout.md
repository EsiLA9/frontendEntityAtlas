# Layout 展示审计

本审计覆盖 `src/data/layout/index.js` 中的 14 条实体。翻译只补充了 `definitionZh` 和 `useZh`，没有改变英文、ID、`type`、`preview.renderer` 或交互字段。

判断依据是当前 `src/views/preview-renderer.js` 的 renderer 选择，以及 `src/components/entity-demo.js` 的分支和实际 DOM 行为。当前 Layout 族没有专用 renderer：部分实体进入 `EntityDemo.buildLayout()`，部分实体因为通用分支的匹配顺序进入 `buildDataDisplay()` 或 `buildGeneric()`。`buildLayout()` 只生成 A、B、C 三个 `span`，初始为水平 flex 行；当实体名称包含 `split` 时初始带有 `is-split` 类，CSS 将其改为纵向排列；按钮会在这两种方向之间切换。三个彩色方块本身不代表已经实现了完整的布局系统，因此本审计不把 `behaviors` 或 `preview.example` 当作实际功能证据。

## 统计

按 `Match` 统计：High **0**、Medium **2**、Low **12**；共 **14** 条审计记录。按 `Significance` 统计：High **0**、Medium **2**、Low **12**。翻译字段 `definitionZh` 和 `useZh` 已为 14 条实体全部补齐。

当前结果表明：只有 Stack 与 Flex 的最基本“一维排列/方向切换”得到部分表达；Grid、Cluster、Center、Resizable、Scroll Area 以及页面级布局实体仍需要专用 renderer，Split、Sidebar Layout、Panel 和 Split Pane 还需要真实区域关系与尺寸交互。多数 Low 评级是当前展示能力的事实记录，不应通过已有的彩色方块或通用按钮上调评级。
