# Feedback 展示审计

本审计覆盖 `src/data/feedback/index.js` 中的 10 条实体。判断依据是当前 `src/views/preview-renderer.js` 的 renderer 映射、`src/components/entity-demo.js` 的分支逻辑，以及 `ProgressBar`、`Skeleton`、`Alert` 专用组件的实际 DOM 和事件行为。`Match` 表示实体声明与当前 demo 的对应程度；`Significance` 表示定义中的关键行为是否能被用户明显感知。

本族中 `progress-bar`、`skeleton`、`alert` 使用专用 renderer；`toast` 和 `snackbar` 虽然进入 `EntityDemo.buildFeedback()`，但共享同一个通用反馈消息 demo；`spinner`、`status-indicator`、`empty-state`、`validation-diagnostic` 使用 `EntityDemo.buildGeneric()`。`async-interaction` 的 renderer 名称包含 `action`，按 `EntityDemo.buildDemo()` 的匹配顺序进入 `buildAction()`。`preview.example` 不会自动替代实际 renderer 的内容，因此审计以用户真正看到的 DOM 和可执行操作为准。

## 逐条审计

| Entity | Claimed concept | Actual demo | Visible result | Interaction | Match | Significance | Gap |
|---|---|---|---|---|---|---|---|
| `progress-bar` — Progress Bar / 进度条 | **Definition:** 显示一项有明确总量的任务已经完成多少。<br>**Use:** 用于上传、安装、导出、导入、生成以及其他可度量进度的任务。 | `preview.renderer = progress-bar`，使用专用 `ProgressBar` renderer；预览参数固定为 `value: 63`、`interactive: true`。 | 可见一条已填充约 63% 的进度轨道和 `63%` 数值标签；组件根节点使用 `slider` 语义以支持交互，并设置当前值为 63。 | 在真实浏览器中点击轨道可按位置更新进度；聚焦后可用左右/上下方向键、Home、End 调整数值，并更新填充宽度、百分比和状态。 | **High** | **High** — 完成量和更新结果都直接可见，用户能立即理解“任务完成了多少”。 | 未演示未开始、暂停、错误、缓冲、分段或不确定进度；没有上传/安装等具体任务上下文，也没有可见的失败消息。 |
| `spinner` — Spinner / 旋转加载指示器 | **Definition:** 用动画表示正在进行的工作，但无法确定完成百分比。<br>**Use:** 用于按钮提交、小型异步请求、页面加载和行内数据刷新。 | `preview.renderer = spinner` 没有专用构造器，回退到 `EntityDemo.buildGeneric()`；`spinner` 不匹配任何专用分支。 | 显示一个通用按钮 `切换状态 / Toggle state`、状态文字 `Ready / 就绪`，以及 `4 states · 4 behaviors` 说明；没有旋转图形。 | 点击通用按钮只在 `Ready / 就绪` 与 `Active / 已激活` 之间切换状态输出和根节点状态；没有开始/停止加载过程。 | **Low** | **Low** — 只有抽象的状态切换可见，用户无法观察动画、处理中语义或未知时长。 | 缺少旋转动画、处理中标签、inline/button/page/overlay 变体、阻塞或允许交互的差异，以及完成/错误后停止。 |
| `skeleton` — Skeleton / 骨架屏 | **Definition:** 在真实数据加载期间预示内容形状的结构化占位符。<br>**Use:** 用于卡片、表格、用户资料、信息流，以及需要保持布局稳定的页面。 | `preview.renderer = skeleton`，使用专用 `Skeleton` renderer；`optionsFor()` 固定传入 `lines: 2`、`width: 85%`、`loaded: false`。 | 可见两条带 shimmer 动画的占位线，宽度分别约为 85% 和 72%；根节点处于 loading、`aria-busy=true`，没有真实内容文本。 | 没有用户可操作控件；加载切换只能通过组件的 `setLoaded()` 程序接口完成，当前预览没有暴露该控制。 | **High** | **High** — 占位线的形状预留和加载动画清楚表达了“内容尚未到达但布局已预留”。 | 未演示 loaded 后的真实内容替换，也没有错误回退、卡片/表格/头像/媒体等不同骨架形态；`interactive: false` 与当前无控件预览一致。 |
| `status-indicator` — Status Indicator / 状态指示器 | **Definition:** 用紧凑的视觉信号传达对象、流程或连接的当前状态。<br>**Use:** 用于在线状态、校验结果、运行时状态、同步状态、健康状况和发布状态。 | `preview.renderer = status-indicator` 没有专用构造器，回退到 `EntityDemo.buildGeneric()`。 | 显示通用按钮 `切换状态 / Toggle state`、`Ready / 就绪` 和 `7 states · 4 behaviors`；没有圆点、图标、标签或状态颜色。 | 点击按钮只切换通用的 Ready/Active 状态；不会在在线、离线、忙碌、成功或错误状态之间切换。 | **Low** | **Low** — 用户看不到“一眼识别状态”的紧凑视觉信号，核心概念不明显。 | 缺少 dot/icon/badge/text 形态、状态标签、颜色语义、实时更新和 hover 详情；`preview.example` 的 `运行中 / Running` 未被渲染。 |
| `empty-state` — Empty State / 空状态 | **Definition:** 针对暂时没有可展示内容的区域而设计的界面响应。<br>**Use:** 用于首次使用、列表已清空、没有搜索结果、缺少权限和加载失败的场景。 | `preview.renderer = empty-state` 没有专用构造器，回退到 `EntityDemo.buildGeneric()`。 | 显示通用按钮 `切换状态 / Toggle state`、`Ready / 就绪` 和 `4 states · 4 behaviors`；没有空内容区域、标题、说明或插图。 | 点击按钮只切换通用 Ready/Active 状态；没有创建内容、清除筛选、申请权限或重试入口。 | **Low** | **Low** — 预览没有呈现“这里没有内容”这一事实，也没有下一步行动。 | 缺少 no data/no results/首次使用/缺少权限/错误等区分、插图、说明、主次操作和恢复流程。 |
| `alert` — Alert / 警告提示 | **Definition:** 因为信息需要用户关注而持续显示的页面级消息。<br>**Use:** 用于校验摘要、系统警告、成功确认、服务中断和重要通知。 | `preview.renderer = alert`，使用专用 `Alert` renderer；`optionsFor()` 固定使用 `severity: success`、`dismissible: true`，标题取中文实体名，消息取英文 `use`。 | 可见一个绿色成功样式的页面级消息，标题为 `警告提示`，消息为 `Validation summaries, system warnings, success confirmation, outages, and important notices.`，旁边有 `×` 关闭按钮；根节点初始为可见 `status`。 | 点击 `×` 会隐藏消息、标记为 dismissed，并发出 `alert:dismiss`；当前预览没有恢复按钮，`restore()` 仅能由程序调用。 | **High** | **High** — 持续存在的消息、重要信息和关闭行为都能直接观察到，足以说明 Alert 与瞬时提示的区别。 | 颜色被固定为 success，未演示 info/warning/error、阻塞、恢复操作或 action；消息使用英文 `use`，未使用新增的 `useZh`；`preview.example` 的 `已保存 / Saved successfully` 也未被采用。 |
| `toast` — Toast / 轻提示 | **Definition:** 报告操作结果但不改变页面布局的瞬时通知。<br>**Use:** 用于反馈保存、复制、上传、失败或后台操作的结果。 | `preview.renderer = toast` 没有专用构造器；因名称匹配 feedback 分支，使用 `EntityDemo.buildFeedback()` 的通用消息 demo。 | 可见 `✓ 操作成功 / Action succeeded` 消息和 `×` 关闭按钮；消息位于普通 preview stage 中，不是独立的通知 viewport。 | 点击 `×` 会隐藏消息并显示 `Dismissed / 已关闭`；没有自动消失、悬停暂停或消息堆叠。 | **Low** | **Low** — 能看到一条可关闭反馈，但“瞬时”“不改变布局”和 toast 专属出现位置都没有被明显表达。 | 缺少进入/退出动画、定时 auto-dismiss、hover pause、stack、action，以及保存/复制/上传等真实触发来源。 |
| `snackbar` — Snackbar / 底部提示条 | **Definition:** 通常固定在视口底部附近、以操作为导向的瞬时消息。<br>**Use:** 用于带撤销操作的删除、离线变更、排队任务以及轻量的后续操作反馈。 | `preview.renderer = snackbar` 没有专用构造器；使用与 `toast` 相同的 `EntityDemo.buildFeedback()` 通用消息 demo。 | 可见普通 stage 内的 `✓ 操作成功 / Action succeeded` 和 `×`；没有底部定位、`撤销` 文本或操作按钮。 | 点击 `×` 隐藏消息并输出 `Dismissed / 已关闭`；没有 Undo、过期计时、队列或操作待处理状态。 | **Low** | **Low** — 通用可关闭消息不能让用户辨认 Snackbar 的底部锚定和短暂可操作特征。 | 缺少 viewport 底部定位、Undo action、action pending、auto-dismiss、排队消息和离线/删除场景。 |
| `validation-diagnostic` — Validation and Diagnostic / 校验与诊断消息 | **Definition:** 结构化说明，用于解释校验、代码检查、运行时或数据质量状况。<br>**Use:** 用于表单、代码编辑器、条件构建器、导入流程以及编辑器的数据完整性检查。 | `preview.renderer = validation-diagnostic` 没有专用构造器，回退到 `EntityDemo.buildGeneric()`。 | 显示通用按钮 `切换状态 / Toggle state`、`Ready / 就绪` 和 `6 states · 5 behaviors`；没有字段标记、严重级别、错误摘要或诊断位置。 | 点击只切换通用 Ready/Active 状态；不能触发校验、定位错误、应用 Quick Fix 或区分 warning/error。 | **Low** | **Low** — 用户无法从预览看到任何校验条件、错误位置或严重程度，结构化诊断概念不可辨认。 | 缺少字段/表单错误、lint 或运行时消息、错误汇总、跳转定位、Quick Fix、阻塞级别和 Pending 状态。 |
| `async-interaction` — Async Interaction Lifecycle / 异步交互生命周期 | **Definition:** 传达操作从空闲进入处理中、成功或失败状态的通用模型。<br>**Use:** 用于保存、发布、获取、上传、删除、自动保存以及其他依赖网络的交互。 | `preview.renderer = async-interaction` 没有专用构造器；由于 renderer 名称包含 `action`，按 `EntityDemo.buildDemo()` 的匹配顺序进入 `buildAction()`。 | 显示通用按钮 `执行动作 / Run action` 和 `Ready / 就绪`；点击后按钮变为 `✓ 已触发 / Triggered`，不显示 `7 states · 6 behaviors` 计数。 | 点击只把按钮标记为已触发并输出 `Action emitted / 动作已触发`；不会经历 Requesting、Confirmed、Failed、Retrying，也不会执行回滚。 | **Low** | **Low** — 只能看见一次同步动作触发，无法理解异步生命周期的顺序和结果分支。 | 缺少请求触发后的 pending 指示器、乐观更新、处理中/成功/失败状态、重试、回滚、网络延迟和后台任务反馈。 |

## 统计

按 `Match` 统计：High **3**、Medium **0**、Low **7**；共 **10** 条审计记录。按 `Significance` 统计：High **3**、Medium **0**、Low **7**。翻译字段 `definitionZh` 和 `useZh` 已为 10 条实体全部补齐。
